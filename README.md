## 🚀 С чего начать

1С — это не просто язык, а платформа с собственной архитектурой, клиент-серверной моделью и жёсткими стандартами разработки. Если пропустить базу, дальше будет больно.

### Минимальный стартовый набор

| Шаг | Что сделать | Зачем |
|---|---|---|
| **1** | Установить **учебную версию** платформы `1С:Предприятие 8.3 / 8.5` | Бесплатно и легально для обучения[reference:0] |
| **2** | Разобраться, чем **платформа** отличается от **конфигурации** | Это фундамент, без которого код превращается в набор заклинаний[reference:1] |
| **3** | Пройти **бесплатный вводный курс** | Понять профессию и базовые механизмы[reference:2] |
| **4** | Создать первую информационную базу и открыть **Конфигуратор** | Руки должны «почувствовать» инструмент[reference:3] |

> 💡 **Правило первого дня:** не пытайтесь выучить «весь 1С». Выучите, как создать справочник, документ и простой отчёт. Этого достаточно, чтобы двигаться дальше.

## 🗺️ Дорожная карта

Ниже — этапы с **критериями выхода**, а не просто список тем. Такой подход используется в открытом роадмапе сообщества `Kelll31/1C-Roadmap`, который опирается на официальную модель компетенций фирмы «1С»[reference:4].

### Этап 0 — Фундамент платформы

- [ ] Установлена учебная версия платформы
- [ ] Понятия: **платформа**, **конфигурация**, **информационная база**
- [ ] Режимы работы: **файловый** и **клиент-серверный**
- [ ] Создана пустая база, открыт Конфигуратор

**Критерий выхода:** можете объяснить, что происходит от нажатия «Запустить 1С:Предприятие» до открытия формы.

---

### Этап 1 — Объекты конфигурации и встроенный язык

- [ ] **Справочники**: реквизиты, табличные части, формы
- [ ] **Документы**: движения, проведение, модуль объекта
- [ ] **Регистры сведений и накопления**: зачем нужны и чем отличаются
- [ ] Базовый синтаксис встроенного языка: переменные, условия, циклы, процедуры и функции[reference:5]
- [ ] Отладчик и типовые ошибки

**Критерий выхода:** собран мини-учёт: справочник + документ + движение по регистру.

---

### Этап 2 — Запросы и отчёты

- [ ] Язык запросов 1С: `ВЫБРАТЬ`, `ГДЕ`, `СГРУППИРОВАТЬ ПО`, соединения
- [ ] **СКД (Система компоновки данных)**: базовые отчёты и настройки[reference:6]
- [ ] Понимание, когда запрос, а когда — обход по объектам
- [ ] Простые печатные формы

**Критерий выхода:** отчёт, который строится по данным ваших документов и регистров.

---

### Этап 3 — Архитектура и командная разработка

- [ ] Клиент-серверное взаимодействие: клиент, сервер, внешнее соединение
- [ ] Общие модули: клиентские, серверные, с повторным использованием
- [ ] **Git** в 1С: выгрузка/загрузка конфигурации, `.gitignore`, ветки[reference:7]
- [ ] Стандарты разработки 1С (ИТС)

**Критерий выхода:** проект в Git, который можно развернуть на другой машине по инструкции.

---

### Этап 4 — Углубление и специализация

- [ ] Интеграции: HTTP-сервисы, обмен данными, внешние источники
- [ ] **1C:EDT** — среда разработки на Eclipse[reference:8]
- [ ] Производительность: индексы, блокировки, анализ запросов
- [ ] Выбор трека: **ERP**, **интеграции**, **мобильная разработка**, **1С:Предприятие.Элемент** и др.[reference:9]

**Критерий выхода:** pet-проект или вклад в open-source 1С.

> ⚠️ **Важно про версии:** ветка `8.3` завершилась на `8.3.27`; дальше используется нумерация `8.5`. Учебные материалы стоит сверять с актуальной документацией, а не с туториалами 2018 года[reference:10].

## 🧰 Ключевые технологии

| Технология | Зачем 1С-разработчику |
|---|---|
| **Конфигуратор** | Основная среда разработки: объекты, формы, модули |
| **1C:EDT** | Разработка на Eclipse, удобна для команд и Git[reference:11] |
| **Язык запросов 1С** | Данные в 1С живут в запросах; без него нет отчётов и оптимизации |
| **СКД** | Стандартный инструмент отчётов, который спрашивают на собеседованиях |
| **Git** | Командная разработка и контроль версий конфигурации |
| **HTTP-сервисы** | Интеграция с сайтами, API, внешними системами |

## 🛠️ Практика и проекты

Без проектов обучение превращается в чтение. Вот проверенная последовательность:

| Проект | Что тренирует |
|---|---|
| **Мини-склад** | Справочники, документы, регистры, отчёты, печатные формы[reference:25] |
| **Учёт заявок** | Документы, движения, простой документооборот |
| **Отчёт по продажам на СКД** | Запросы, СКД, настройки |
| **HTTP-обмен с сайтом** | Интеграция, HTTP-сервисы[reference:26] |
| **Своя конфигурация под задачу** | Всё вместе: от структуры до интерфейса |

**Правило:** каждый проект должен быть в **Git**. Даже если вы учитесь один — это тренирует привычку, которую ждут на работе.

## 🎓 Сертификация

Сертификаты фирмы «1С» — не панацея, но полезный ориентир и иногда — требование работодателя.

| Уровень | Что сдавать |
|---|---|
| **Профессионал** | `1С:Профессионал` — базовый экзамен по платформе |
| **Специалист** | `1С:Специалист` — практический экзамен по разработке |
| **Специалист-консультант** | Для консультантов по внедрению |

**Совет:** готовьтесь к сертификации **после** первого реального проекта. Иначе это будет заучивание без понимания.

## 💡 Советы новичку

1. **Не учите всё сразу.** 1С огромен. Двигайтесь этапами: платформа → объекты → запросы → архитектура.
2. **Пишите код каждый день.** Даже 30 минут практики лучше 3 часов видео.
3. **Читайте чужой код.** Открытые конфигурации и репозитории сообщества — лучший учебник.
4. **Ведите проект в Git.** С первого дня. Это гигиена разработчика.
5. **Задавайте вопросы.** В сообществе 1С отвечают охотно, если вопрос сформулирован конкретно.
6. **Сверяйте версии.** Материалы 2019 года могут быть опасны для `8.5`[reference:36].
